# SaaS Platform Project Implementation Report (Phase 1 - 30% Milestone)

This document provides a comprehensive overview of the technical implementation completed for the first 30% of the SaaS Platform Final Year Project (FYP). 

Our initial objective was to establish a robust full-stack foundation, implement secure user authentication with multi-tenancy, and build the core infrastructure for the AI-powered Retrieval-Augmented Generation (RAG) Knowledge Base.

---

## 1. Architectural Foundation
We adopted a modern, decoupled architecture ensuring high performance and scalability.

### Technology Stack
- **Frontend**: React 18, Vite, TypeScript, Tailwind CSS, Lucide React (Icons).
- **Backend**: FastAPI (Python), SQLAlchemy (ORM), SQLite (Local Database), JWT (Authentication).
- **AI/ML Pipeline**: LangChain, FAISS (Vector Database), HuggingFace Sentence-Transformers (`all-MiniLM-L6-v2`), PyPDF.

---

## 2. Implemented Modules

### Module 1: Authentication & Multi-Tenancy
To support a B2B SaaS environment, we implemented a strict multi-tenant architecture where data is completely isolated between different companies.

- **User Registration & Login**: Functional UI and API endpoints (`/api/users/signup`, `/api/users/login`) with secure password hashing.
- **JWT Authorization**: All secured API endpoints require a valid Bearer token.
- **Tenant Isolation**: Upon signup, a unique `Tenant` profile is automatically generated. Every subsequent resource (Databases, Documents) is strictly bound to the `tenant_id` of the requesting user.

### Module 2: External Database Connection Management
SaaS platforms often need to connect to user databases to extract or analyze data. We built a management module for these connections.

- **Database Registry**: Users can save database connection credentials (Host, Port, Username, Password) for various database types (PostgreSQL, MySQL, MongoDB).
- **API Endpoints**: CRUD operations under `/api/databases`.
- **UI Integration**: A dedicated "Databases" page where users can view their active connections and simulate "Testing" the connection status.

### Module 3: RAG Knowledge Base & Document Pipeline
This is the core AI infrastructure required for the eventual Chatbot Widget. We built a fully local, privacy-first vectorization pipeline.

- **File Upload Engine**: Users can securely upload `.pdf` and `.txt` files via the `/api/documents/upload` endpoint.
- **Background Processing**: Heavy AI vectorization runs asynchronously using FastAPI's `BackgroundTasks`, keeping the UI responsive.
- **Semantic Extraction**:
  - Text is extracted using `PyPDF` and native Python file handling.
  - The text is split into semantic chunks using LangChain's `RecursiveCharacterTextSplitter`.
- **Local Embedding Generation**: We integrated HuggingFace's `sentence-transformers` to generate semantic vector representations of the text chunks entirely locally (no API keys required).
- **FAISS Vector Database**: The vectors, along with explicit metadata (Document ID, Source Name), are stored in local FAISS indices, separated by `tenant_id`.

### Module 4: Knowledge Base UI & Observability
We built a highly interactive interface to manage the AI embeddings.

- **Dynamic Metric Cards**: The UI calculates and displays Total Documents, Storage Used, and the exact count of Total Vector Embeddings in real-time.
- **Vector Observability**: Users can click "View Embeddings" on any processed document to open a modal that displays the exact raw text chunks generated by the AI, ensuring complete transparency.
- **Cascade Deletion**: When a user deletes a document, the backend intelligently scrubs the specific vector chunks from the FAISS database before deleting the SQLite record, preventing vector database bloat.

## 3. Current Project State & Next Steps

At this 30% milestone, the platform is fully capable of securely ingesting users, securely saving external database connections, and running a complete end-to-end AI document vectorization pipeline.

**Upcoming Milestones (Next 30%):**
1. **Chatbot Widget Integration**: Connecting the vectorized FAISS knowledge base to a Large Language Model (e.g., OpenAI API or a local LLaMA model) to allow natural language querying against the uploaded documents.
2. **Dashboard Analytics**: Implementing data visualization charts using Recharts to display fake or extracted business metrics.
3. **API Key Management**: Allowing users to input and securely store their own OpenAI/Cohere API keys for custom model processing.
