# Demo QA remediation — 22 October 2026

The ten findings from the [original live review](../demo_qa_2026-10-21/REPORT.md) have been addressed. The app and all three demo database servers remain running. Planner V2 remains opt-in; its default was not changed.

## Corrections and verification

- **DQA-01 — Historical growth:** Removed the frontend's reconstruction of previous values from arbitrary KPI percentages. Period comparison now uses observed time-series periods. Browser verification shows only the actual September/October comparison; the invented Top Market previous value and +41.1% growth row are gone.
- **DQA-02 — Consistent filtered populations:** SQL customer counts follow the scoped fact population. Unit totals follow a declared line-to-fact foreign key; unsupported joins produce unavailable values rather than global totals. East coffee now returns $12,400 revenue, 60 orders, **6 customers, 240 units, and $2,066.67 spend per customer**. Filtered requests cannot reuse the unfiltered L2 cache. Mongo dimension filters now also scope distinct metrics and never fall back to unfiltered counts on query failure; unrelated collections are unavailable under a collection-specific filter.
- **DQA-03 — Widget retrieval:** Reciprocal-rank fusion now identifies individual passages by chunk ID, index, or content digest instead of collapsing all passages with a missing chunk index into one document entry. The widget uses the same tenant/document-scoped parent context builder as dashboard chat. Both widget known-answer tests returned the correct coffee 30 days / $100 and Orbit 1 business hour, with supported grounding. Origin checks remain allowed-localhost 200 / unapproved-origin 403.
- **DQA-04 — Grounding:** Verification uses the same expanded evidence as generation, comparing atomic claims against paragraphs and sentences as well as whole contexts. Evidence from another document cannot be attached as a child's parent. Heading-only text, citation page numbers, and follow-up questions are excluded from factual coverage; policy-table rows retain their meaning. Candidate support still requires the existing semantic threshold and numerical/negation checks. All three dashboard policy answers were observed with **supported / coverage 1.0** after the fixes. Citation snippets point to supporting passages. The UI no longer labels every unsupported answer as a contradiction.
- **DQA-05 — Mongo chatbot:** Added a Pydantic-validated read plan in `backend/services/mongo_query.py`, dispatched before the SQL path. Generation and execution validate collection/field access against the live catalog. Allowed stages are match, group, sort, limit, project, and count. Writes, code execution, cross-collection stages, system collections, unknown fields, sensitive fields, oversized/deep plans, and unsupported operators are rejected. Execution has row/time/response-size bounds and closes clients/cursors. Nested sensitive fields are masked. Catalog BSON date/datetime fields bind ISO bounds as actual datetimes. Live queries returned **160 invoices / $16,300**, **$14,736 paid**, and **60 invoices / $6,140 in October**. A native Mongo SSE response ended with `done=true` and the correct $14,736 result.
- **DQA-06 — Summaries:** PostgreSQL/MySQL `Decimal` aggregates are normalized before availability checks, prompt construction, and fallback calculations. This was the live-only cause of correct metrics being called insufficient data. Safe, fixed metric names accompany numeric aggregates without forwarding arbitrary user labels or identities. The live fallback now states **$30,200 across 240 records**, and **$12,400 across 60 records** under East scope.
- **DQA-07 — Rankings:** Rankings honor each chart's `yKey` and use null-aware value extraction. Browser output now shows East 12,400, South 8,700, North 6,200, and West 2,900 instead of four zeros.
- **DQA-08 — Invalid table scope:** The service rejects nonexistent table/dimension identifiers rather than choosing another table. The HTTP router returns **422 with a clear scope error**, while retaining error audit recording. The previously expected-failing missing-table regression is now a normal passing rejection test.
- **DQA-09 — Fallback honesty:** An unavailable document synthesis explicitly says it could not verify an answer; it no longer substitutes unrelated excerpts as an answer. Streaming can persist an honest supplied fallback if the provider fails before its first token, while callers without a fallback retain pre-token failover behavior. The unspecified loyalty conversion rate was explicitly identified as unspecified in a live response. A real quota-limited Orbit attempt produced an honest fallback; its subsequent successful retry returned the correct facts with full grounding. Both attempts are retained in evidence.
- **DQA-10 — Paid billing:** Mongo Insights distinguishes the all-status amount sum from an explicit paid-status amount. The fixture returns **$16,300 gross billed versus $14,736 paid**. Under cancelled-only scope it returns **16 invoices, $1,564 billed, $0 paid, and 1 distinct status**; the paid predicate intersects the requested filter instead of overwriting it. Unsupported MRR/churn metrics are not invented.

## Remaining boundaries

External Gemini/Groq quota and service availability remain outside the app's control. The remediation makes outages explicit and preserves verified calculations; it cannot guarantee successful generation on every request while upstream quotas are exhausted. Successful retries are recorded separately from failed attempts, not treated as uninterrupted availability.

The Mongo planner deliberately supports a restricted read-only aggregation subset, not arbitrary MongoDB code or joins. Unsupported requests fail closed. Bounded catalog sampling may not discover rare fields. Existing process-local caches/rate limiting, multi-worker behavior, high-concurrency load, PDF/OCR extraction, mobile layout, and broad arbitrary-schema parity were not certified by this task. The demo connections remain isolated local development assets using generated administrator credentials; they are not a production database-access configuration.

Source fixes, test fixtures, and notes remain in the working tree for review. No merge, push, deployment, user credential reset, source-data reseed, or additional cleanup was performed during remediation.
